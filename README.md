# Магазин Timur Shorabekov

Интернет-магазин PDF-книг и руководств Тимура Шорабекова с оформлением заказов и личной консультацией.

## Что уже готово

- каталог товаров
- форма заказа
- генерация заказа и итоговой суммы
- подготовка оплаты через Halyk ePay
- автоматическая отправка материалов на email после оплаты
- готовый деплой для Render
- домен: `timurshorabekov.kz`

## Быстрый запуск

```bash
npm install
cp .env.example .env
npm start
```

Откройте: http://localhost:4000

## Переменные окружения

Заполните `.env` по примеру из `.env.example`.

Ключевые параметры для реальной работы:

- `HALYK_EPAY_CLIENT_ID`
- `HALYK_EPAY_CLIENT_SECRET`
- `HALYK_EPAY_TERMINAL_ID`
- `PUBLIC_BASE_URL=https://kaplyaznani-store.onrender.com` (публичный адрес Render для callback и возврата Halyk; меняйте на собственный домен только после проверки DNS и привязки домена к сервису)
- Google Apps Script mailer URL и секрет для отправки писем
- `CRM_ADMIN_PASSWORD` — пароль для закрытой CRM-страницы `/admin/traffic`

## Render

1. Загрузите этот проект в GitHub.
2. На Render создайте новый Web Service из GitHub repo.
3. Выберите ветку `main`.
4. Используйте команду запуска:
   ```bash
   npm start
   ```
5. В настройках добавьте переменные из `.env.example`.
6. Подключите домен `timurshorabekov.kz` в Render и настройте DNS у вашего регистратора.

## Настройка домена

Для домена `timurshorabekov.kz` обычно используйте CNAME/ALIAS на Render и подключите custom domain в панели Render.

Если используете Cloudflare, настройте DNS как:

- `A` или `CNAME` → Render endpoint
- `www` → CNAME → ваш Render домен

## Halyk ePay

Магазин создаёт отдельную платёжную сессию EPAY2 для каждого заказа. Карточные данные вводятся только на стороне Halyk:

1. Сервер получает одноразовый OAuth-токен Halyk.
2. В браузере открывается платёжный виджет EPAY2 с суммой заказа.
3. Halyk отправляет уведомление на `https://timurshorabekov.kz/api/payment/callback`.
4. Сервер самостоятельно проверяет статус, сумму, валюту и терминал через API Halyk.
5. Письмо со ссылками Drive отправляется только после подтверждённого статуса `CHARGE`.

Для настройки скопируйте `.env.example` в `.env` локально или задайте переменные в Render:

- `HALYK_EPAY_MODE=production`
- `HALYK_EPAY_CLIENT_ID` — логин/client ID EPAY2
- `HALYK_EPAY_CLIENT_SECRET` — client secret EPAY2; хранить только в серверных секретах
- `HALYK_EPAY_TERMINAL_ID` — идентификатор терминала
- `BOOK_ACCESS_SECRET` — отдельный постоянный секрет для подписанных ссылок на программу «Включение»; хранить только в серверных секретах
- `PUBLIC_BASE_URL=https://timurshorabekov.kz`

Для прямой интеграции EPAY2 используется `HALYK_EPAY_CLIENT_SECRET`. `TildaSecret` и callback URL обработчика Tilda не используются: магазин принимает уведомления по адресу `/api/payment/callback`.

В Tilda можно использовать показанные логин, секрет заказа и терминал, если банк подтвердил, что секрет заказа является `ClientSecret` для EPAY2 OAuth. Секрет, отправленный в переписке, следует заменить в панели Halyk и использовать новый в настройках сервера.

Для тестовой среды задайте `HALYK_EPAY_MODE=test`. Не используйте production credentials для тестирования. Страницы возврата магазина: `/payment/success` и `/payment/failure`.

После подтверждённой оплаты «Включения» покупатель получает подписанную ссылку на программу `/program/vklyuchenie`. Без действительной ссылки сервер отказывает в доступе. Задайте постоянный `BOOK_ACCESS_SECRET` в Render Secrets (если он не задан, используется Halyk Client Secret). Не меняйте секрет после выдачи ссылок, иначе старые ссылки перестанут работать. Ссылку можно переслать, поэтому не публикуйте её открыто.

Записи ПЕГАС-40 сохраняются только в браузере покупателя и не отправляются в Google Таблицы. Очистка данных браузера может удалить прогресс; на странице есть экспорт резервной копии.

Заказы сейчас хранятся в памяти процесса. Перед масштабированием или использованием нескольких экземпляров Render нужно подключить постоянное хранилище заказов, иначе перезапуск процесса может потерять незавершённый заказ до получения банковского callback.

## Автоматическая отправка материалов

После успешной оплаты система отправляет покупателю письмо с доступом к материалам, а для «Включения» — также уведомление магазину. Чтобы не зависеть от заблокированных на Render SMTP-портов и платных сервисов, отправка идёт через бесплатный Google Apps Script mailer, работающий от имени вашего Google-аккаунта.

Настройка mailer (один раз):

1. Откройте [script.google.com](https://script.google.com/) под Gmail-аккаунтом, с которого нужно отправлять письма, и создайте проект.
2. Скопируйте содержимое [`google-mailer/Code.gs`](./google-mailer/Code.gs) в редактор и сохраните.
3. В **Project Settings → Script Properties** создайте `MAILER_SECRET` с длинным случайным значением. Используйте отдельный секрет, не пароль Gmail или Halyk.
4. В тех же **Script Properties** задайте `SPREADSHEET_ID` — идентификатор таблицы между `/d/` и `/edit` в её URL. Скрипт создаст в ней вкладки `ПЕГАС-40` и `Посещаемость`; не делайте таблицу общедоступной.
5. Запустите функцию `setupDailyCleanup` из редактора Apps Script один раз и подтвердите разрешение на создание ежедневного триггера. Записи и аналитика старше 12 месяцев будут удаляться ежедневно.
6. Нажмите **Deploy → New deployment → Web app**. Выберите запуск от своего аккаунта и доступ **Anyone**, затем подтвердите разрешения на отправку почты и изменение таблицы. Скопируйте URL веб-приложения.
7. В Render → **Environment** задайте `GOOGLE_MAILER_URL` (URL веб-приложения), `GOOGLE_MAILER_SECRET` (то же значение, что `MAILER_SECRET`) и уникальный `CRM_ADMIN_PASSWORD`. Удалите старые `SENDGRID_*` и `GOOGLE_OAUTH_*` переменные.

Веб-приложение принимает только запросы с правильным секретом; секрет хранится в Script Properties и Render Secrets, не в Git. Бесплатная квота Gmail ограничивает объём ежедневной отправки и может изменяться Google. Если меняете код Apps Script после публикации, создайте новую версию deployment.

Участник программы может отдельно согласиться на отправку дневных записей и заметок в закрытую Google Таблицу. Записи удаляются через 12 месяцев. Статистика сайта собирает путь страницы, источник перехода и тип устройства; IP-адреса и полные URL перехода не сохраняются. CRM доступна по `/admin/traffic` после Basic Auth (логин `admin`, пароль `CRM_ADMIN_PASSWORD`).

При подтверждённой оплате книги «Включение» магазин дополнительно отправляет на `STORE_NOTIFICATION_EMAIL` имя, телефон, email покупателя и номер заказа. Если переменная не задана, используется `CONTACT_EMAIL`.
